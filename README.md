# AstraEmojis

A standalone Paper 1.21.x emoji plugin for Java 21. It contains **no donut-shop, economy, or shop code**.

## What was found in `GGDonutShop.jar`

The emoji-related implementation is concentrated in two classes:

* `SpriteComponentReplacer` scans text with `<sprite:...>` or `:[A-Za-z0-9_]+:`. Its built-in shortcodes map `:yt:`, `:india:`, `:star:`, `:check:`, `:heart:`, and `:donut:` to private-use glyphs `U+E001` through `U+E006`. It creates Adventure text components, explicitly uses `minecraft:default`, and disables inherited italics on the glyph.
* `NxSpriteResolver` first discovers the separately installed `dev.nx.emojis.api.NxEmojisApi` service by reflection and calls `replace(Component, ":<material-name>:")`. If that service is unavailable it falls back to Paper's modern Adventure sprite object component, choosing an `items` or `blocks` atlas and a Minecraft item/block texture. It contains overrides for materials whose texture path is not mechanically predictable.
* `PaperDialogue` calls that resolver to put sprite components into the shop's Paper dialogs. The jar itself contains **no font JSON or PNG files**; its `NxEmojisApi` integration expects those to be supplied by a separate emoji plugin/resource pack. Thus the reusable method in this repository is the shortcode → private-use glyph → `minecraft:default` bitmap-provider pipeline, with Adventure components throughout.

AstraEmojis generalizes that same method: mappings are data-driven in `emojis.yml`, text leaves are parsed into styled Adventure components, and generated font providers bind each glyph to its PNG. With `auto-material-emojis` enabled, all non-legacy Bukkit items/blocks also receive generated mappings backed by their vanilla texture path (a same-named PNG overrides it). Unknown codes remain text, `\:name:` is escaped, and URL/code tokens are not parsed.

## Build

Requirements: JDK 21 and an internet connection for Gradle dependencies.

```bash
gradle clean build
# build/libs/AstraEmojis-1.0.0.jar
```

Paper is `compileOnly`; ProtocolLib is an optional `compileOnly` dependency. Install ProtocolLib 5.3+ to intercept UI generated by other plugins.

## Setup

1. Put `AstraEmojis-1.0.0.jar` in the Paper server's `plugins/` folder.
2. Start once, then put square or rectangular PNGs in `plugins/AstraEmojis/emojis/`, for example `lime_wool.png`.
3. Add/adjust mappings and permissions in `emojis.yml`. PNGs without entries receive stable `U+E000` private-use mappings automatically.
4. Set `resource-pack.public-url` to a publicly reachable HTTPS URL. The built-in HTTP server is convenient for testing, but its inferred player-address URL is normally unsuitable for production/proxies.
5. Run `/emoji reload`. Upload `plugins/AstraEmojis/generated/AstraEmojis-pack.zip` at the configured URL if not using the embedded server.
6. Players can type `:lime_wool:`, `:pink_harness:`, or any configured/PNG-derived name.

The generated pack writes `assets/minecraft/font/default.json`, references Minecraft's built-in `minecraft:include/default` providers, and adds one bitmap provider per available PNG. Keep `resource-pack.pack-format` aligned with the exact client version (the shipped value is for 1.21.6).

## Commands and permissions

| Command | Purpose |
|---|---|
| `/emoji list` | Clickable list of emojis available to the sender |
| `/emoji reload` | Reload YAML, discover PNGs, rebuild/restart the pack service |
| `/emoji give <name>` | Give a paper token showing/copying a shortcode |
| `/emoji pack` | Re-send the generated resource pack |

* `astraemojis.use` — base use permission (default true)
* `astraemojis.use.<name>` — per-emoji permission
* `astraemojis.use.*` — every emoji
* `astraemojis.admin` — reload/give and all emoji permissions

An entry with a blank `permission` only requires `astraemojis.use`.

## Supported surfaces

Native Paper listeners cover chat, signs, books, and anvil results. The optional ProtocolLib output bridge covers Adventure/chat fields in tab headers/footers, scoreboard objectives/teams/scores, entity metadata (text displays and armor stands), inventory titles/items, boss bars, and 1.21.6+ dialog packets when those packet types are exposed by the installed ProtocolLib build. Every surface has a `config.yml` toggle.

Item names and lore in outgoing slot/window packets are transformed on a clone for the recipient, so server-side items are not modified. Other plugins can avoid packet interception and call the API directly.

Minecraft does not request server command suggestions while a player types ordinary chat. Consequently true live `:name:` completion in the vanilla chat field is not possible without a client mod; `/emoji` arguments do provide server tab completion, and `/emoji list` offers click-to-copy codes.

## Public API

```java
Component parsed = AstraEmojisAPI.parse("Hello :donut:");
Component checked = AstraEmojisAPI.parse("Hello :donut:", player);
Optional<Emoji> emoji = AstraEmojisAPI.getEmoji("donut");
```

`AstraEmojisService` is also registered with Bukkit's `ServicesManager`. `EmojiManager` is the central implementation and exposes `replace(String)` and `replace(Component)` plus player-aware overloads.

## Notes

* Signed chat is changed through Paper's `AsyncChatEvent`, not by rewriting signed chat packets.
* Packet support is deliberately version-tolerant: packet constants are discovered by name, and an unknown field layout never cancels delivery.
* Resource-pack hosting must be reachable from players' computers, not only from the Minecraft server.
